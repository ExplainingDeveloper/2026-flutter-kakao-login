# Flutter 카카오 로그인 적용

이 스킬은 Flutter 앱에 카카오 로그인을 붙이는 작업을 여러 단계로 나눠 진행한다.
사용자는 한국인이다. 질문, 진행 안내, 완료 보고는 모두 자연스러운 한국어로 작성한다.
이 스킬은 Claude Code 외의 에이전트(GitHub Copilot 등)에서도 쓰일 수 있다. 지침에 나오는 질문 도구(AskUserQuestion)가 없으면 같은 내용을 채팅으로 묻는다.
코드, 파일 경로, XML/plist 키는 원문 그대로 둔다.

## 단계 목록

| 번호 | 단계 | 지침 파일 |
|---|---|---|
| 0 | 준비 – 카카오 디벨로퍼스 콘솔 설정, 로그인 버튼 이미지 (사용자 직접) | `references/step-00-prepare.md` |
| 1 | 프로젝트 설정 – 커스텀 URL 스킴 (Android / iOS) | `references/step-01-custom-url-scheme.md` |
| 2 | SDK 설치 및 초기화 (pubspec.yaml, main.dart) | `references/step-02-install-and-init.md` |
| 3 | 카카오 로그인 로직 (카카오톡 / 카카오계정 로그인, 로그인 버튼, 로그인 화면) | `references/step-03-login-logic.md` |
| 4 | 사용자 정보 가져오기 (홈 화면) | `references/step-04-user-info.md` |
| 5 | 자동 로그인 (토큰 확인) | `references/step-05-auto-login.md` |
| 6 | 로그아웃 / 연결 끊기 (회원 탈퇴) | `references/step-06-logout-unlink.md` |

표의 순서가 곧 "전체" 실행 순서다.
새 단계를 추가할 때는 `references/step-NN-<이름>.md`를 만들고 이 표에 한 줄을 추가한다.

## 진행 순서

### 1. 프로젝트 확인

- 현재 디렉터리(또는 사용자가 알려준 경로)에 `pubspec.yaml`이 있고 `flutter:` SDK 의존성이 있는지 확인한다.
  Flutter 프로젝트가 아니면 이유를 알려주고 멈춘다.
- `android/`, `ios/` 폴더가 있는지 확인한다. 한쪽이 없으면 해당 플랫폼 작업은 건너뛰고, 건너뛴다는 사실을 사용자에게 알린다.

### 2. 실행할 단계 고르기

- 스킬 인자(`$ARGUMENTS`)나 사용자 메시지에 단계 번호(예: `1`, `1단계`)나 `전체`/`all`이 있으면 그대로 따른다.
- 없으면 물어본다. 선택지 질문 도구(예: Claude Code의 AskUserQuestion)가 있으면 그것을 쓰고, 없으면 채팅으로 번호를 물어본다.
  - 질문 예: "어떤 단계를 진행할까요?"
  - 질문 본문에 위 단계 목록을 번호와 함께 적는다.
  - 선택지 (AskUserQuestion은 최대 4개라서 단계별 선택지를 모두 넣을 수 없다):
    - `전체 진행 (0→6단계)`: 처음 시작하는 경우
    - `0단계만: 준비`: 콘솔 설정과 버튼 이미지 안내만
    - `코드 작업만 (1→6단계)`: 콘솔 설정을 이미 마친 경우
  - 특정 단계 하나만 하려면 "Other"에 번호를 입력하라고 질문 본문에 적는다.
- `1-3`, `1~3`처럼 범위를 받으면 그 범위의 단계를 순서대로 진행한다.

### 3. 공통 정보 모으기 (네이티브 앱 키)

1, 2단계는 **네이티브 앱 키**가 필요하다.
- 실행할 단계 중에 1, 2단계가 없으면 이 과정은 건너뛴다.
- 키는 1 또는 2단계를 시작하기 직전에 받는다. "전체"로 실행하면 0단계에서 사용자가 콘솔에서 앱을 만든 뒤에 키를 받게 된다.
- 한 번만 받아서 이후 모든 단계에 다시 쓴다. 같은 질문을 두 번 하면 사용자가 번거롭다.

1. 먼저 프로젝트에 이미 키가 있는지 찾는다.
   - `android/app/src/main/AndroidManifest.xml`, `ios/Runner/Info.plist`에서 `kakao[0-9a-f]{32}` 패턴을 찾는다.
   - `lib/` 아래에서 `nativeAppKey`를 찾는다.
   - 찾았으면 "기존에 설정된 키 `xxxx…`를 사용할까요?"라고 확인한다.
2. 없으면 사용자에게 받는다. 위치도 안내한다:
   **카카오 디벨로퍼스 > 내 애플리케이션 > [앱] > 플랫폼 키 > 네이티브 앱 키**
3. 형식을 검증한다.
   - 앞뒤 공백을 지운다.
   - 사용자가 `kakao1234…`처럼 접두어를 붙여 입력했으면 `kakao`를 떼고 사용한다.
   - 남은 값은 32자리 16진수여야 한다.
   - 대문자가 섞여 있으면 소문자로 바꿔서 쓰고, 바꿨다고 알린다. 카카오 앱 키는 항상 소문자이고, 스킴과 SDK 초기화에 쓰는 키가 정확히 같아야 하기 때문이다.
   - 길이가 다르거나 16진수가 아닌 문자가 있으면 키를 다시 받는다. 다시 물어볼 수 없는 상황이면 멈추고 이유를 알린다. 틀린 키로 파일을 고치면 사용자가 나중에 원인을 찾기 어렵다.
   - REST API 키, JavaScript 키도 형식이 같아서 겉모습으로는 구분할 수 없다. 잘못된 키를 넣으면 로그인 후 앱으로 돌아오지 못한다. 그래서 "네이티브 앱 키가 맞는지" 안내 문구로 한 번 짚어준다. 작업을 멈추고 묻는 질문은 아니다.

### 4. 단계 실행

- 선택한 단계의 지침 파일을 읽고 그대로 따른다. 지침 파일은 필요할 때만 읽는다.
- **전체**를 골랐으면 표 순서대로 진행한다.
  - 각 단계가 끝날 때마다 한두 줄로 진행 상황을 알린다. 예: "✅ 1단계 완료 – 다음은 2단계입니다."
  - 어떤 단계가 실패하면 그 자리에서 멈추고, 원인과 해결 방법을 알린다. 다음 단계가 앞 단계 결과에 의존하기 때문이다.

### 5. 완료 보고

모든 실행이 끝나면 한국어로 짧게 정리한다.

- 진행한 단계
- 변경한 파일과 변경 내용 요약 (이미 설정되어 있어 건너뛴 항목도 표시)
- 사용자가 직접 해야 할 일 (예: 카카오 디벨로퍼스 콘솔 설정)
- 다음에 진행할 수 있는 단계. 마지막 단계까지 끝났으면 기기에서 `flutter run`으로 로그인을 테스트해 보라고 안내한다.

## 화면 연결 기준

이 스킬은 화면을 새로 만들지 않는다. 로그인 기능(서비스, 버튼)을 만들고, 이미 있는 화면에 연결한다. 프로젝트 종류에 따라 연결 방법이 다르다. 처음 판단한 결과를 이후 단계에도 그대로 쓴다.

- **스타터 프로젝트** (GitHub `ExplainingDeveloper/2026-flutter-kakao-login`의 main 브랜치)
  - 판단 기준: `lib/` 안에 `// TODO(카카오 N단계)` 표시가 있다.
  - 할 일: 각 단계의 지침대로, 해당 단계 번호가 적힌 TODO 자리에 코드를 연결한다. 연결이 끝난 TODO 주석은 지운다.
  - 단계 번호가 다른 TODO는 건드리지 않는다. 나중 단계에서 쓴다.
  - 화면 흐름: 로그인 화면 → 홈 화면(사용자 정보, 로그아웃, 회원 탈퇴)
- **그 외 프로젝트** (사용자 자신의 앱)
  - 화면 파일을 만들거나 고치지 않는다. 사용자가 만든 화면, 라우터, 상태 관리를 망가뜨릴 수 있다.
  - 서비스 메서드와 버튼 위젯만 만들고, 기존 화면에 붙이는 사용 예시를 완료 보고에 적는다.
  - 예외: `main.dart`가 Flutter 기본 템플릿(`Hello World`나 카운터 예제) 그대로라면, 3단계에서 그 자리에 버튼만 넣어 동작을 확인할 수 있게 한다.
  - 사용자가 화면도 만들어 달라고 하면 그 요청을 따른다.

## 작업 원칙

- **다시 실행해도 안전하게**: 이 스킬은 여러 번 실행될 수 있다. 이미 있는 설정은 중복으로 추가하지 않는다. 키만 다르면 키만 바꾼다.
- **기존 설정 보존**: 파일 전체를 새로 쓰지 않는다. 필요한 부분만 Edit로 고친다. 사용자 프로젝트에는 다른 SDK(구글 로그인, 딥링크 등) 설정이 있을 수 있다.
- **수정 전 확인**: 파일을 먼저 읽고 현재 상태를 파악한 뒤 수정한다.
- **카카오 패키지 import는 설치된 패키지에 맞춘다**: 단계별 코드 예시는 `package:kakao_flutter_sdk_user/kakao_flutter_sdk_user.dart`를 쓴다. 프로젝트에 전체 패키지(`kakao_flutter_sdk`)만 있으면 모든 파일에서 `package:kakao_flutter_sdk/kakao_flutter_sdk.dart`로 바꾼다. `pubspec.yaml`에 없는 패키지를 import하면 `depend_on_referenced_packages` 경고가 난다.
